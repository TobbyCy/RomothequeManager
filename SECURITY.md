# Sécurité — signalement responsable

**Ne publiez aucun secret, vulnérabilité exploitable, preuve brute, log sensible, chemin personnel ou donnée de collection réelle dans une Issue, une PR ou une Discussion.**

## Contacter le responsable

Le dépôt est en préparation privée et **aucun canal de signalement intégré n'est déclaré activé ou vérifié**. Si GitHub affiche une option **Report a vulnerability** sur ce dépôt, utilisez-la uniquement après avoir vérifié qu'il s'agit d'un formulaire privé. Sinon, ouvrez au maximum une **demande de contact sans détail technique sensible** ; n'exposez pas les étapes d'exploitation. Attendez la confirmation d'un canal privé convenu avec le mainteneur avant de transmettre un dossier complet.

Un signalement de sécurité ne doit pas être classé comme bug public reproductible. Ni les Issues ni les PR ne constituent un coffre-fort.

## Périmètre et données

Les seules données destinées aux tests de ce dépôt sont synthétiques. Ne joignez pas de ROM/BIOS, sauvegarde, XML ES-DE réel, StateRoot, log de disque ou identifiant matériel. Aucun contrôle CI n'autorise une exécution sur des données utilisateur. Une faille concernant une future fonctionnalité non implémentée doit être qualifiée **hypothétique**, pas présentée comme exploit observé.

## Publication et correctifs

Le mainteneur coordonnera la réponse, la revue, le correctif, les tests et une publication adaptée lorsqu'ils seront réellement disponibles. **Aucune garantie de délai de réponse n'est donnée ici.** Le canal privé, les versions supportées et l'activation de GitHub Security Advisories devront être recontrôlés avant un éventuel passage PUBLIC.
